# SSE 省电闸门只拦自动重试，显式连接永远能发出第一次尝试
- 日期：2026-10-19
- 状态：已采纳
- 关联约束：INV-001、INV-002、INV-003
- 关联坑点：pitfalls/2026-10-19-manual-pairing-deadlock-after-auto-search-off.md

## 背景

2.5.x 为治「夜间对关机电脑空转重连」（ai-handover.md §7 #25）给 `SseClient` 加了省电门控：
每轮循环开头查 `nextRetryDelayMs`，窗口关闭且未连接返回 null 即退出。2.6.0 实测发现
门控把**手动 PIN 配对成功后的首次连接**也闸死了（详见关联坑点）——门控在首轮尝试
之前生效，而首轮尝试恰恰是每个 `connect()` 调用方的存在意义。

同时要解决一个次生问题：`connect()` 内部先调 `disconnect()` 作废旧代，其同步回调
`onConnectionChanged(false)` 会把调用方刚置位的 `connectionState=1` 当场冲回 0，
这正是门控首轮看到「未连接」的直接原因。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）：门控后移到首轮之后（`isFirstAttempt` 豁免）+ connect() 换代静默（`teardown(notify=false)`） | 语义干净：「闸门管自动不管手动」；connect() 调用方无需知情；顺带消除假掉线回调引发的 `onPcDisconnected()` 误触发 | 窗口关闭期每次显式 connect() 会多一次 TCP 尝试（可忽略的电量）；首轮失败后仍按 null→2s 兜底睡一次再退出 |
| B：在 `nextRetryDelayMs` lambda 里特判「刚配对成功」（状态位或时间戳） | 不动 SseClient | 把「显式意图」编码进调度策略，每多一个调用方就要多一个特判；配对成功标志与 SSE 线程生命周期脱节，易腐烂 |
| C：`connect(url, explicit: Boolean)` 逐级传递意图 | 意图显式化 | 全部调用方签名连带修改；未来新调用方忘传参即回退为被闸；lambda 侧仍要区分 |

## 结论与理由

选 A。`connect()` 的全部现有调用方（PIN 配对成功、自动握手成功、IP 漂移热重连）都代表
「明确的立即连接意图」，且自动路径在上游已被自己的闸门过滤（`onDeviceDiscovered` 的
搜索窗口闸门、配对模式闸门），显式路径不该再被省电闸门二次拦截。首轮豁免后，首轮失败
→ 第二轮起门控照常生效，省电承诺不受损（最坏情况 = 每次用户操作多一次 TCP 尝试）。

**未来应重新评估的条件**：出现「窗口关闭期连一次尝试都不允许」的硬省电诉求（如按电量
百分比联动）；或 `connect()` 新增无法归入「立即连接意图」的调用方（届时应先审视该
调用方是否该走自己的调度，而不是给门控加特判）。

配套决定：「自动搜索」开关重开时，已连接只重置窗口（INV-003），不全量重扫——
`triggerRescan()` 的定位是「用户主动要求重新找电脑」，不是开关的附属动作。
