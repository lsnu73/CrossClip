# CrossClip 项目地图（lore）

这份地图回答代码说不清的问题：**为什么这样设计、动哪里会扯动哪里、哪些约束不能碰**。
它面向没有任何上下文的接手者。与 `docs/ai-handover.md`（交接契约，偏全貌与规范）互补：
本目录按「约束 / 决策 / 坑」分库，逐条可检索、可引用。

## 项目是什么

CrossClip 是一个局域网内 **Windows 电脑 ⇄ Android 手机** 的剪贴板与文件互传工具：
手机端是常驻前台服务（Kotlin），电脑端是托盘程序（Rust），全部流量不出局域网，
用 6 位 PIN 派生密钥做端到端加密。

## 三个核心业务概念

1. **连接状态机**——「已连接」不是一盏灯，而是 SSE 长连接存活（`connectionState`）
   与握手派生状态（`currentPcIp` 等）两份事实的合成；两者脱节叫「状态分裂」。
2. **省电时间窗**——未连接时一切后台搜索/重连共用一张「0–5 分钟高频 / 5–9 分钟每分钟 /
   9–15 分钟每 2 分钟 / 15 分钟停止」的降频表，由 `LanDiscovery` 统一驱动。
3. **显式意图 vs 后台自动**——用户的每一个明确动作（点「连接」、重开开关）都不是
   「后台自动行为」，凡闸门逻辑必须区分这两者（本目录 invariants 的前三条由此而来）。

## 推荐阅读顺序

1. `glossary.md`——先统一术语，代码里同义词很多；
2. `invariants.md`——硬约束清单，改代码前过一遍；
3. `map.md`——模块拓扑与依赖箭头；
4. 要动某个模块时，再读它条目里引用的 `decisions/` 与 `pitfalls/`。

## 读完全部仍卡住时

- 规范类问题（构建、通知、断开语义）看 `docs/engineering-rules.md`；
- 协议字段问题看 `docs/protocol.md`；
- 历史 bug 根因总表看 `docs/ai-handover.md` §7；
- 都没有就把双端日志按时间对齐重放一遍（本目录坑点条目都是这么定位的）。
